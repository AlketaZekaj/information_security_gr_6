# jose configuration notes

The default path uses only the key import and `jwtVerify(token, key)`, matching the README-level setup. It deliberately does not supply issuer, audience, required claims, an algorithm allow-list, or clock tolerance.

The hardened path adds `algorithms: ['RS256']`, issuer, audience, `requiredClaims: ['iss', 'aud', 'exp']`, and `clockTolerance: 0`.

All 401 responses are generated by this wrapper rather than by `jose`; `X-Reject-Reason` records the thrown error class for comparison. This is a limitation when comparing response bodies across targets.

The exact package versions are pinned in `package.json`. `package-lock.json` must be generated and committed with `npm install` before Docker is run; Docker intentionally uses `npm ci`.

## Pre-run predictions

These predictions are written before running the matrix, as required by the study protocol.

| Test | Predicted default | Predicted hardened | Reason |
|---|---|---|---|
| CTRL-01 | accept | accept | Valid control token. |
| ISS-INVALID | accept | reject | Default does not pass `issuer`; hardened does. |
| ISS-MISSING | accept | reject | Default does not require `iss`; hardened uses `requiredClaims`. |
| AUD-INVALID | accept | reject | Default does not pass `audience`; hardened does. |
| AUD-MISSING | accept | reject | Default does not require `aud`; hardened uses `requiredClaims`. |
| EXP-EXPIRED | reject | reject | JWT lifetime validation is expected when `exp` is present; hardened also requires it. |
| EXP-MISSING | accept | reject | Hardened explicitly requires `exp`; default does not. |
| NBF-FUTURE | reject | reject | `nbf` is expected to be validated when present. |
| NBF-MISSING | accept | accept | `nbf` is not required. |
| ALG-NONE | reject | reject | An imported RSA public key cannot verify an unsigned token. |
| ALG-UNEXPECTED | reject | reject | Hardened has an explicit RS256 allow-list; default should fail key/algorithm verification. |
| ALG-CONFUSION | reject | reject | RSA verification key cannot validate an HMAC signature. |
| SIG-TAMPERED | reject | reject | Signature verification fails. |

The default predictions above are intentionally hypotheses until tested against the pinned jose version. Any mismatch must be added below with the token result, HTTP status, and `X-Reject-Reason` value.
